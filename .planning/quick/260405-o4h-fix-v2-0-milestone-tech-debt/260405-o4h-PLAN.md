**backend/worker.py** — expand `full_result` at lines ~174-180:

The worker already has `company_name` and `model` as function parameters. The `updated_at` value is computed by `_now_iso()` immediately before the DB write at that point in execution. `created_at` is NOT in local scope and requires a DB fetch — but the frontend self-corrects via sidebar polling within 30 seconds, so set `created_at` to `None` (matches the `str | None` shape frontend should handle gracefully) rather than adding a DB round-trip. Per AUDIT: severity=medium, self_corrects=true.

Replace the `full_result` dict with:
```python
_completed_at = _now_iso()
full_result = {
    "id": job_id,
    "status": "complete",
    "company_name": company_name,
    "model": model,
    "created_at": None,      # not in local scope; frontend self-corrects via 30s poll
    "updated_at": _completed_at,
    "tailored_cv": tailored_cv.model_dump(),
    "gap_diff": [g.model_dump() for g in gap_diff],
    "pdf_url": f"/api/jobs/{job_id}/pdf",
}
```

Also pass `_completed_at` to the DB UPDATE instead of calling `_now_iso()` a second time (same timestamp, avoids a tiny clock drift between DB write and SSE push):
```python
# In the DB execute call above full_result, replace _now_iso() with _completed_at
```

This requires defining `_completed_at = _now_iso()` before the `db = await get_db()` call that does the complete transition (around line 154). Move the assignment there.
